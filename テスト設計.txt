範囲観点条件を検討
テスト設計方針の検討
テスト計画では、テストレベルとタイプを検討
テスト設計方針では、さらに詳細にテスト範囲観点条件を検討

テスト範囲の検討
テスト計画で洗い出したテスト範囲の中でテストするところとしないところを決める。
機能をより細かく分解


テスト観点
テストの目的からかんがみてテストで確認すべきこと
観点を見つけ出す3つの方法
（１）仕様書の記述通りに動作するかを確認
　できることとできてはいけないことを考える。
（２）仕様書に記述はないが、一般的にあるべき動作を確認
　できるべきこと（あるべき姿）とできてはいけないことを考える。
（３）類似の機能の不具合から類推する
　「値保持」「入力保持」

テスト条件
入力データやバリエーション
あらゆるバリのテストは非現実的のため、計画で決めた優先度を踏まえ網羅する基準を決める。
テスト設計方針の段階では、テスト技法を用いて具体的な入力やパターンをだすことまではしない。
どのテスト観点に対し、どの技法を使用するのか、網羅する基準をどうするかまで決めておく。

状態遷移テスト（テスト技法）
【　】状態、《　》イベント
発生しても処理が起きないイベント：ー
起こりえないイベントN/A
状態遷移図を用いたテストのテストケースのつくり方
SWの「できること」を図に表し確認する方法
・すべての状態を１回は通る
・全てのイベントを１回は発生させる
・全ての遷移を１回は通る
加えてユーザのシナリオに沿って見直す
状態遷移表を用いたテストのテストケースのつくり方
SWの「できること」に加え、「できないはずのこと」も確認する方法
１つの升目を１つのテストケースとしてみなす

① 正常系（タイマが発火して遷移する）
C に遷移してから T2 秒後に E2 が発火 → D へ変わる
D に遷移してから T3 秒後に E3 が発火 → E へ変わる
E に遷移してから T4 秒後に E4 が発火 → A へ戻る


② タイムアウト前のイベント処理（タイマ待ち中の動作確認）
例：C に入ってタイマが動いている間に…

E2 以外のイベント（E1, E3, E4, E5, E6）が来たらどうなるか？

ほとんどは「ー（無処理）」なので、
テスト観点

タイマ待ち中でも無処理イベントを受けて状態が変化しないこと
タイマはそのままカウントし続けること

これは結構バグが入りやすい部分です。

③ タイマキャンセル（状態離脱時の動作）
例：

C に入った直後に、E2 が発火する前に別イベント（E6 など）で離脱したら？
C →（他イベント）→ A となった場合、
C用のタイマ（E2）はキャンセルされないと不具合です。

テスト観点

状態離脱時にその状態のタイマが確実に停止すること
その後タイマが誤発火しないこと


④ タイマリセット（同じ状態に入り直した場合）
例：
C → D → C（E2 → 別遷移 → また C）
のように、同じ状態に再入したときの挙動確認。
テスト観点
再入時にタイマが再スタートされる
以前のタイマ残り時間が残らない
再入後の正しい時間で発火する

⑤ 並行タイマの独立性テスト
パターン1：前状態のタイマが停止していること（旧タイマ誤発火防止）
✔ C → D に遷移した瞬間
E2（Cのタイマ）が完全に無効化されていることを確認

条件：D に遷移したあと
観察：E2 が誤って発火しない
目的：旧タイマが残って動かないこと

✔ D → E のとき
E3 の動作を確認しつつ E2 が発火しないことを確認
✔ E → A のとき
E4 の動作を確認しつつ E2/E3 が発火しないことを確認

パターン2：次状態のタイマだけが動作する（アクティブ切替の排他性）
遷移後に「その状態専用のタイマだけがスタート」しているかを確認するテスト。
例：
C → D の直後  
D用タイマ E3 だけが走っている  
C用タイマ E2 は停止  
E用タイマ E4 は起動していない

これを3状態すべてで確認：

C に入った直後：E2 だけ動作
D に入った直後：E3 だけ動作
E に入った直後：E4 だけ動作

パターン3：タイマが二重起動しない（duplicate start対策）
開発でよくあるバグ：

状態遷移時に 旧タイマが stop される前に新タイマが start され
2つのタイマが並行発火する

項目：

C → D で E3 が2回生成されていないか
D → E で E4 が2回生成されていないか
E → A → C（ループ後）で E2 が2回生成されていないか

パターン6：E4（E→A）が動いているときに E2/E3 が誤作動しないか
E 用タイマ E4 が発火待ちの間に、

E2 が動いてしまう/発火する
E3 が動いてしまう/発火する

という“実装バグ”が起こり得る。
これを監視して防止を確認。

パターン8：状態に入らないのにタイマだけ発火しないこと
例：

C に入らずに E2 が発火 → NG（異常）
D に入らずに E3 が発火 → NG
E に入らずに E4 が発火 → NG

重複列でフィルタのトライ
=IF(COUNTIFS($F:$F,F2,$G:$G,G2)>1,"重複","")
$F:$F → 期待値列（例：OK / NG）
F2 → 現在の行の期待値
$G:$G → 観点列（例：正常系 / 異常系）
G2 → 現在の行の観点
COUNTIFS(...) → 「期待値と観点が同じ行の数」を数える
>1 → 1件より多ければ重複
IF(...,"重複","") → 重複なら「重複」と表示
